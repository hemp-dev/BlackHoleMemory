# Справочник MCP-инструментов BlackHoleMemory

BlackHoleMemory предоставляет полнофункциональный **Model Context Protocol (MCP)** сервер, работающий по протоколу Streamable HTTP. Через MCP агенты (Codex, Claude, Cursor, Windsurf, Antigravity) сохраняют и запрашивают контекст проекта, исследуют граф кода, ведут чекпоинты и управляют задачами.

---

## Настройка подключения

Канонический локальный URL-адрес сервера MCP:

```text
http://127.0.0.1:8000/mcp
```

### Пример конфигурации для `mcpServers` (Claude Desktop / Cursor / Antigravity):

```json
{
  "mcpServers": {
    "bhm": {
      "url": "http://127.0.0.1:8000/mcp"
    }
  }
}
```

Перед использованием убедитесь, что сервер запущен (`uv run bhm start`) и эндпоинт готовность возвращает HTTP 200 (`curl http://127.0.0.1:8000/health/ready`).

## Категории инструментов MCP

### 1. Поиск и сборка контекста (Search & Context Compilation)

* **`bhm_search`**: Выполняет семантический и гибридный поиск по памяти текущего проекта. Исключает архивные записи и логи ошибок, если они не запрошены явно.
* **`bhm_search_advanced`**: Расширенный поиск с фильтрацией по категориям, временным меткам, тегам и уровням важности.
* **`bhm_context_compile`**: Собирает ограниченный, оптимизированный по токенам контекст проекта с цитатами для текущей задачи.
* **`bhm_explain_retrieval`**: Объясняет взвешивание, ранжирование и задействованные сигналы релевантности при извлечении памяти.

### 2. Управление записями памяти (Memory Lifecycle)

* **`bhm_get_memory`**: Получить запись памяти по её уникальному `id`.
* **`bhm_list_memories`**: Получить список активных записей памяти с фильтрацией по проекту и типам.
* **`bhm_upsert_memory`**: Создать или обновить запись памяти с использованием явного ключа upsert.
* **`bhm_update_memory`**: Обновить существующую запись памяти по `id`.
* **`bhm_delete_memory`**: Удалить запись памяти из хранилища master SQLite.
* **`bhm_archive_memory`**: Перевести запись памяти в архив без физического удаления.
* **`bhm_crystallize`**: Создать агрегированную (кристаллизованную) запись-резюме из нескольких выбранных записей памяти.

### 3. Организация и связывание знаний (Knowledge Organization)

* **`bhm_get_memory_links`**: Получить список связей выбранной памяти с другими записями.
* **`bhm_link_memories`**: Создать направленную связь между двумя записями памяти.
* **`bhm_unlink_memories`**: Удалить связь между двумя записями памяти.
* **`bhm_pin_memory`** / **`bhm_unpin_memory`**: Закрепить/открепить ключевую запись памяти для оперативного доступа.
* **`bhm_list_pinned_memories`**: Получить список всех закреплённых записей проекта.
* **`bhm_merge_memories`**: Объединить две схожие записи памяти в одну.
* **`bhm_detect_duplicates`**: Автоматически обнаружить дубликаты записей памяти.
* **`bhm_detect_conflicts`**: Обнаружить противоречащие друг другу записи памяти.

### 4. Граф кода и архитектурный анализ (Code & Architecture Intelligence)

* **`bhm_code_graph_query`**: Выполнить запрос к графу кода (поиск зависимостей, вызовов функций, структур).
* **`bhm_change_impact`**: Оценить потенциальный риск и зону влияния (Change Impact) при изменении конкретных файлов или символов.
* **`bhm_search_code`**: Поиск по семантическому индексу исходного кода.
* **`bhm_conventions`**: Запросить или сохранить принятые соглашения по кодингу и архитектуре данного проекта.

### 5. Сессии, Чекпоинты и Архитектурные решения (ADR)

* **`bhm_checkpoint_create`**: Создать фундаментальный чекпоинт состояния проекта.
* **`bhm_checkpoint_list`**: Получить список всех доступных чекпоинтов.
* **`bhm_checkpoint_get_latest`**: Получить последний созданный чекпоинт проекта.
* **`bhm_task_open`** / **`bhm_task_close`**: Открыть и закрыть задачу с сохранением контекстной сессии.
* **`bhm_handoff_create`** / **`bhm_handoff_list`**: Создать или просмотреть запись передачи контекста другому агенту или инженеру.
* **`bhm_adr_create`** / **`bhm_adr_list`** / **`bhm_adr_supersede`**: Регистрация и управление архитектурными решениями (Architecture Decision Records).

### 6. Безопасность, Диагностика и Администрация

* **`bhm_health`**: Проверка работоспособности и статуса переключения компонентов BHM.
* **`bhm_health_slo`**: Оценка показателей SLO, очереди обработки и вектора.
* **`bhm_diagnostics`**: Компактный отчет о состоянии зависимостей BHM.
* **`bhm_preflight`**: Запуск предполётной проверки доступности памяти для проекта.
* **`bhm_forget_preview`**: Предварительный просмотр плана безопасного и обратимого удаления контекста.
* **`bhm_forget_apply`**: Применение ранее согласованного плана удаления (требуются права администратора).
* **`bhm_memory_lint`**: Линтинг записи памяти на предмет избыточности, компактности и утечек секретов.
