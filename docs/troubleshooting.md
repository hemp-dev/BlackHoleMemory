# Диагностика и устранение неполадок BlackHoleMemory

В данном документе приведены пошаговые инструкции по диагностике и решению распространенных проблем при работе с BlackHoleMemory.

---

## 1. Экспресс-диагностика через CLI

Первым шагом при возникновении любых проблем запустите встроенную диагностику:

```bash
uv run bhm doctor
```

Команда `bhm doctor` проверяет:
- Среду Python и операционную систему;
- Наличие и целостность базы данных SQLite (`inspect_memory_store_schema`);
- Доступность API-сервера на порту 8000;
- Статус работы Docker Engine и контейнера Qdrant.

---

## 2. Недоступность эндпоинта `/health/ready`

Если запрос `curl http://127.0.0.1:8000/health/ready` возвращает ошибку или HTTP 503:

1. **Проверьте запуск Qdrant**:
   ```bash
   uv run bhm qdrant start
   ```
   Убедитесь, что контейнер `bhm-qdrant` запущен и порт `6333` отвечает на запросы (`curl http://127.0.0.1:6333/readyz`).

2. **Перезапустите сервер BHM**:
   ```bash
   uv run bhm start
   ```

---

## 3. Проблемы с подключением MCP-клиентов

Если ваш AI-агент не видит инструменты `bhm_*`:

1. Проверьте правильность указываемого URL: `http://127.0.0.1:8000/mcp` (протокол Streamable HTTP).
2. Проверьте статус MCP-сервера с помощью инструмента `bhm_health` или через CLI.
3. Убедитесь, что фаервол или локальный прокси не блокируют порт `8000`.

---

## 4. Расхождение векторной проекции Qdrant и SQLite Master

Если семантический поиск не находит свежие записи или возвращает устаревшие ссылки:

Запустите утилиту согласования векторных проекций:

```bash
python scripts/bhm_reconcile_projection.py
```

Скрипт сверит отпечатки в Qdrant с записями в SQLite WAL и восстановит пропущенные или рассинхронизированные векторы.

---

## 5. Повторная обработка мертвых очередей (Dead-Letter Queue)

Если фоновые задачи или хуки завершились с ошибкой:

```bash
python scripts/requeue-bhm-dead-letters.py
```

---

## 6. Очистка и оптимизация базы данных

Для сжатия файла SQLite и оптимизации индексов WAL выполните:

```bash
python scripts/bhm_vacuum.py
```

---

## 7. Куда обращаться и отправка отчетов

При формировании отчета об ошибке в issue репозитория прикладывайте:
- Вывод команды `uv run bhm doctor`;
- Обезличенный ответ от `/health/ready`;
- Описание шагов воспроизведения.

> [!WARNING]
> Перед отправкой логов или отчетов убедитесь, что в них отсутствуют секреты, токены, ключи API и личные пути файловой системы.
